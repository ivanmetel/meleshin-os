# Симуляция: Карточка проекта + Все проекты

Симуляция переработки карточки проекта и списка проектов. Назначение —
показать переработанную карточку до внесения изменений в производственную CRM.

Основа — консолидированное ТЗ "Карточка проекта" от 23.09.2026 (рабочее ТЗ).
Шапка — по ТЗ 2.1, кнопок в шапке нет. Восемь табов по ТЗ 2.2: Основное,
Задачи, Документы, График, Финансы, Тендер, Фото и видео, Кабинет клиента;
таб с содержанием, ещё не описанным в ТЗ, не скрывается — показывается
с состоянием [ ]. "Редактировать" в каждом табе отвечает только за открытый
таб; изменение данных вкладки выполняется её собственными действиями.

- Основное: кнопки "Редактировать" (окно реквизитов, ТЗ 2.2.1.1) и "История"
  (ТЗ 2.2.1.2); видны "Вид работ" и "Заметки"; состав работ и его конструктор
  — "Редактировать состав" (добавление, изменение, перемещение, исключение
  строк; "Весь объект" — общие работы). После сохранения состав попадает
  в рабочие редакции обоих бюджетов; несохранённые изменения в бюджеты
  не попадают.
- Задачи: "Добавить задачу" — карточка задачи (Задача, Описание, Автор,
  Ответственный, Дедлайн, Статус, необязательная связь с работой состава);
  клик по строке открывает карточку с постоянным номером; таблица
  # / Задача / Автор / Дата создания / Дедлайн / Ответственный / Статус;
  фильтры — статус, ответственный, просроченные.
- Документы: внутри вкладки — вкладки управления документами
  Все / Входящие / Исходящие / Внутренние (один реестр; тип, направление
  и статус — отдельные признаки); "Добавить документ" — карточка документа;
  клик по строке открывает карточку; жизненный цикл по направлению;
  КП и зафиксированные версии бюджетов находятся здесь с позициями
  и выгрузкой PDF — фиксация внутреннего бюджета создаёт внутренний
  документ, согласование Бюджета клиента — исходящий черновик
  (согласование ≠ отправка).
- Финансы: Сводный → Внутренний бюджет → Бюджет клиента → Фактический
  труд по табелям → Финансовые операции. Состав и количества — из "Основного";
  внутренняя и клиентская цены хранятся независимо; рабочая редакция —
  единственное место правки цен; позиция с изменённой работой или единицей
  помечается "требует проверки цены" до ввода цены. Над сводкой выбираются
  версии бюджетов для расчёта и период факта. "Зафиксировать" (внутренний)
  и регистрация согласования (клиентский) создают новые неизменяемые версии;
  после согласования изменения копятся в рабочей редакции с признаком
  "изменено относительно согласованного" и дельтой итога. "Сформировать КП" —
  отбор позиций (все оценённые или дополнительный состав вне согласованного
  бюджета), КП становится исходящим документом с версией и выгрузкой PDF;
  внутренние цены и ставки сотрудников в выгрузку не попадают. Труд по
  табелям распределяется по работам состава, часы без связи помечены
  "Не распределено по работам". "Добавить операцию" — карточка финансовой
  операции; новая запись не подтверждена и в денежные итоги не входит.
- Страница "Все проекты" — фильтр по этапу (ТЗ 2.1 п.3) и кнопка
  "Добавить проект" (ТЗ 3.1: Название с автонумерацией YYNN, Клиент, Этап,
  Состояние, даты, Вид работ, Заметки).

Ролевой модели нет — всем видно всё. Правки демо хранятся в памяти страницы
до перезагрузки.

## Данные

Все данные демонстрационные: вымышленные проекты "2608. Peyia Villa",
"2607. Polis Apartment", "2604. Nicosia Office", вымышленные клиенты, прорабы,
подрядчики и суммы. Реальная информация в репозитории не содержится.

## Запуск

Открыть `index.html` в браузере, либо поднять локальный сервер:

```
python3 -m http.server 8080
```

и открыть http://localhost:8080

## Маршруты

| Адрес | Страница |
|---|---|
| `#/vse-proekty` | Все проекты (фильтр этапов) |
| `#/<проект>/<таб>` | Карточка проекта, например `#/2607-Polis-Apartment/osnovnoe` |
| `#/<таб>` | Карточка проекта по умолчанию (2607) — прежний формат ссылок |

Табы: `osnovnoe`, `zadachi`, `dokumenty`, `grafik`, `finansy`, `tender`,
`foto-video`, `kabinet-klienta`.

## Файлы

| Файл | Роль |
|---|---|
