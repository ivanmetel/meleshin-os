# Симуляция: Карточка проекта + Все проекты

Симуляция переработки карточки проекта и списка проектов. Назначение —
показать переработанную карточку до внесения изменений в производственную CRM.

Основа — ТЗ модуля "Карточка проекта" (`tz/project-card/` в Meleshin-OS):
модульный спек + спеки разделов (Основное, Объект, Задачи, Документы,
График, Финансы, Тендер [ ], Кабинет клиента [ ]). Переработка по планам
рефакторинга 26.09 и логики проекта 27.09: Объект (перечень помещений,
элементы и измерения), Основное (состав со стадиями и раскрытием позиции),
Финансы (единая страница "Сметы" — рабочая редакция и зафиксированные
редакции, формулы с промежуточным округлением, КП с объединением строк),
График (нормы, идеальный расчёт длительностей, версии плана), этапы
проекта с триггерами: согласование КП переводит предпроектный этап
в СМР, согласование акта закрывает охваченные работы, а при отсутствии
открытых — переводит проект в пост-проектные работы.
Шапка — по ТЗ "Карточка проекта" (шапка); реквизиты шапки редактируются
кнопкой "Редактировать" в табе "Основное". Восемь табов
по ТЗ "Карточка проекта" (табы): Основное, Объект, Задачи, Документы,
График, Финансы, Тендер, Кабинет клиента; таб с содержанием, ещё не
описанным в ТЗ, не скрывается — показывается с состоянием [ ].
"Редактировать" в каждом табе отвечает только за открытый таб; изменение
данных вкладки выполняется её собственными действиями.

- Основное: кнопки "Редактировать" (окно реквизитов — с полем "Название",
  где YYNN-префикс присваивается при создании и не редактируется) и
  "История"; видны "Вид работ" и "Заметки"; состав работ
  # / Стадия / Помещение / Работа / Ед. / Кол&#8209;во и его конструктор
  "Редактировать состав" (стадия — из перечня 1–19; помещение выбирается
  из перечня "Объекта", для общих работ — "Весь объект"; элемент — из
  данных помещения). Клик по строке открывает позицию с её десятью
  сведениями (идентификатор, стадия, помещение, элемент, работа, единица
  и количество, подсчёт объёма, основание, связанные работы, норма [ ]).
  Состав и количества — источник для "Финансов"; копии позиций там нет.
- Объект: единый перечень помещений — источник помещений для состава
  работ, расчёта, задач и табелей; добавление, переименование (переносится
  на привязанные позиции состава), исключение (исключение помещения
  с привязанными позициями — [ ], в демо не выполняется); системное
  значение "Весь объект" существует всегда и не редактируется. Раскрытие
  помещения — элементы и изделия с измерениями и происхождением каждого
  значения (лист ПД, запись design-data, ручной ввод с основанием).
  Размеры хранятся в "Объекте"; в расчёт передаётся результат подсчёта
  объёма работы. Элементы [ ]: объёмы по помещениям, фото и видео.
- Задачи: "Добавить задачу" — карточка задачи (Задача, Описание, Автор,
  Ответственный, Дедлайн, Статус, необязательная связь с работой состава);
  клик по строке открывает карточку с постоянным номером; таблица
  # / Задача / Автор / Дата создания / Дедлайн / Ответственный / Статус;
  фильтры — статус, ответственный, просроченные.
- Документы: плоский реестр # / Документ / Тип / Дата / Статус. Статус —
  последнее событие документа по словарю (Черновик, Зафиксирован,
  Отправлен, Получен, Согласован с клиентом, Утверждён внутри компании);
  события регистрируются с датой, исполнителем и подтверждением
  и не стирают друг друга. Фиксация сметы, фиксация плана и выпуск КП
  добавляют сюда документы с выгрузкой PDF; в карточке счёта оплатенность
  ("не оплачен / оплачен частично / оплачен") вычисляется
  из распределённых поступлений и вручную не устанавливается.
- График: рабочая редакция календарного плана и зафиксированные версии.
  Строки — подробные позиции состава; объединённый КП строк графика
  не порождает. Норма подбирается по составу и единице (файл норм,
  демо-версия 2026-05; при нескольких подходящих побеждает самая
  конкретная — больше совпавших ключей; норма окраски с включённой
  подготовкой не применяется к строке одной окраски); назначение нормы
  и ручная длительность с основанием — в раскрытии строки. Расчёт:
  Трудоёмкость = Кол&#8209;во × Норма; Длительность в сменах =
  MAX(1, CEIL(Трудоёмкость ÷ (2 × 8))) — округление каждой строки до
  целой смены; календарь пн–сб, воскресенье — выходной, паузы —
  в календарных днях; независимые последовательности идут параллельно.
  Начальная дата задаётся явно. У строки показывается состояние работы
  позиции ("Запланирована", "В работе", "Выполнена", "Исключена").
  "Зафиксировать план" сохраняет версию плана (состав, нормы,
  длительности, даты, предпосылки, календарь) документом в "Документах"
  и для сравнения с рабочей редакцией: добавлено, исключено, изменение
  длительности.
- Финансы: Сводный → Сметы → Фактический труд по табелям → Финансовые
  операции. Сметы — единственное место изменения цен и коэффициентов:
  три таблицы (работы, материалы, прочие) с итогами по себестоимости
  и продажной стоимости; строка считается формулами Себестоимость =
  ROUND(Кол&#8209;во × Вн. цена за ед.; 2), Цена за ед. = ROUND(Вн. цена
  за ед. × Коэф. 1 × Коэф. 2; 1), Стоимость = ROUND(Кол&#8209;во ×
  Цена за ед.; 2). Коэф. 2 применяется только к строительно-монтажным
  и отделочным работам и добавляется в расчёт проекта с назначением
  (вознаграждение дизайнера — плановый расход от прироста, в цену
  клиенту второй раз не добавляется). Материалы допускают предварительную
  оценку границами диапазона: обе границы — значения строки, в итог —
  границами. Действия "Зафиксировать" и "Сформировать КП" сохраняют
  редакцию со значениями и источниками; сохранённые редакции
  не пересчитываются, признак "изменено относительно согласованного"
  и дельта итога показываются. КП формируется по продажным ценам:
  объединяются совместимые работы (одинаковая работа, единица
  и рассчитанная цена), количество объединённой строки — сумма количеств;
  при разных ценах строки остаются раздельными, усреднённая цена
  не появляется; внутренние цены, коэффициенты и вознаграждение
  дизайнера в КП не попадают. Согласование КП сохраняет ориентировочный
  характер предложения и окончательную смету не создаёт. Сводный — 14
  показателей, включая "Продажную оценку", "Закупочную оценку",
  "Вознаграждение дизайнера", "Не оплачено по счетам", "Аванс клиента",
  "К оплате сейчас"; цепочка по умолчанию — последняя согласованная
  смета, при её отсутствии согласованное КП (ориентировочно), затем
  рабочий расчёт (черновик); "Остаток по смете" показывается только
  после согласования уточнённой сметы. Типы операций: поступление,
  расход, возврат (связан с исходной операцией, уменьшает её сторону),
  внутренний перевод (в денежных итогах проекта не участвует).
  Подтверждённое поступление распределяется по счетам клиента;
  нераспределённый остаток — аванс клиента.
- Страница "Все проекты" — фильтр по этапу и кнопка "Добавить проект"
  (Название с автонумерацией YYNN, Клиент, Этап, Состояние, даты,
  Вид работ, Заметки).

Правки демо хранятся в памяти страницы до перезагрузки.

## Данные

Все данные демонстрационные: вымышленные проекты "2608. Peyia Villa",
"2607. Polis Apartment", "2604. Nicosia Office", вымышленные клиенты, прорабы,
подрядчики и суммы. Реальная информация в репозитории не содержится.

## Запуск

Открыть `index.html` в браузере, либо поднять локальный сервер:

```
python3 -m http.server 8080
```

и открыть http://localhost:8080

## Маршруты

| Адрес | Страница |
|---|---|
| `#/vse-proekty` | Все проекты (фильтр этапов) |
| `#/<проект>/<таб>` | Карточка проекта, например `#/2607-Polis-Apartment/general` |
| `#/<таб>` | Карточка проекта по умолчанию (2607) — прежний формат ссылок |

Идентификатор таба — слаг раздела из реестра ТЗ (`tz/registry.md`):
`general`, `facility`, `tasks`, `documents`, `schedule`, `finance`,
`tender`, `client-portal`. Прежние транслитерации (`osnovnoe`, `grafik`,
`kabinet-klienta` и другие) перенаправляются на слаги.
